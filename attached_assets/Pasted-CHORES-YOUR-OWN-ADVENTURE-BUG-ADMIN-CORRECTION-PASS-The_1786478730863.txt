1. QUEST STATE IS CURRENTLY INCONSISTENT ACROSS SCREENS

Current actual behavior:

* Home shows an active quest card.
* Quest Hub → My Quests says there are no active quests.
* Give Me a Quest says:
    “All clear! No quests available right now.”
* The exact same Home screen visibly shows an active assigned quest directly underneath.

This is a major logic bug.

The app is clearly using different quest filters/data sources in different places.

Fix this at the root.

There should be ONE canonical definition of:

ACTIVE QUEST FOR CURRENT USER

Home, Quest Hub, Give Me a Quest, and Quest Details must all derive from the same persisted quest/assignment data and the same eligibility logic.

Do not fix each screen separately with custom exceptions.

⸻

2. DEFINE A CANONICAL ACTIVE-QUEST QUERY

Create/reuse one shared server-side or domain-layer function for current-user quest eligibility.

Conceptually, an active assigned quest should qualify when:

* it belongs to the currently selected Party;
* the current user/adventurer is an assignee;
* the assignment/occurrence status is active/available;
* it is not already completed;
* it is not awaiting verification unless specifically shown in a verification state;
* it has not expired;
* recurring scheduling conditions currently allow it.

Use this same canonical logic for:

* Home → Your Quests
* Quest Hub → My Quests
* Give Me a Quest
* Quest counters/badges
* Quest Details navigation

Do not duplicate filtering logic in multiple components.
